## In 3 lines

- **What it is:** An AI agent is a language model that can use tools, look at the results, and decide its next step by itself, again and again, until the job is done.
- **Why it matters:** A chatbot only answers. An agent can actually do work, like searching, editing files, or booking a meeting.
- **Example:** You ask, "Fix the broken link on my site." The agent finds the page, edits it, checks the result, and tells you when it is fixed.

## Think of it like…

<Analogy>
A chatbot is like calling a friend for advice. They tell you what to do, and then you do it.

An agent is like hiring a helper with the keys to your house. You give the goal. They walk around, open drawers, try things, and come back when it is done.

**Where the comparison breaks:** A human helper has common sense about your house. An agent only knows what you told it and what its tools show it.
</Analogy>

## Real-world example

A small online shoe store gets 200 support emails a day. Many ask, "Where is my order?"

With a **chatbot**, a staff member pastes the email in, reads the suggested reply, opens the shipping system, finds the order, and writes back. The model only helped with the wording.

With an **agent**, the model gets the email plus two tools: "look up order" and "send reply." It reads the email and calls the order tool with the order number. Then it reads the tracking status and writes the reply. If the order number is missing, it asks the customer for it instead of guessing. Staff only check the tricky cases.

## How it works

Every agent is built from three parts:

1. **A model** — a large language model (LLM), the AI that reads text and writes text. It does the thinking.
2. **Tools** — actions the model is allowed to ask for, like "search the web" or "run this code." Your program runs the tool, not the model.
3. **A loop** — the program keeps going round until the task is finished.

One trip around the loop looks like this:

1. The model reads the goal and everything that has happened so far.
2. It decides on one next action and asks for a tool.
3. The program runs the tool and gives the result back to the model.
4. The model checks the result. Is the job done? If not, go back to step 1.

```text title="The agent loop"
 Goal ──► Model decides next step ──► Tool runs
              ▲                            │
              └──── not done ◄── Result ◄──┘
                                   │
                                  done ──► Answer
```

*The diagram shows the loop: decide, act, see the result, repeat until done.*

This "think, then act, then look" pattern was described in a 2022 research paper called **ReAct**. It showed that mixing reasoning steps with actions works better than doing only one of them.

**Agent or workflow?** Anthropic draws a useful line. In a **workflow**, a programmer fixes the steps in advance in code. In an **agent**, the model chooses its own steps. Workflows are more predictable. Agents are more flexible, but cost more and are harder to control.

## Common mistakes

- **Using an agent when one model call would do.** Agents are slower and cost more. Try a single, well-written request first and add a loop only if you need it.
- **No stopping rule.** An agent can loop forever or keep making the same mistake. Set a limit, such as a maximum number of steps.
- **Vague tools.** The model only knows what a tool does from its name and description. Write tool descriptions as clearly as you would for a new coworker.
- **No human checkpoint for risky actions.** Sending money or deleting data should pause for a person to approve.
- **Small errors pile up.** One wrong step early can send the whole run in the wrong direction. Test in a safe sandbox before giving real access.

## Remember this

<Remember>
- Agent = model + tools + loop.
- The model picks the next step; your program runs the tool and feeds back the result.
- Use the simplest thing that works: one call, then a workflow, and only then an agent.
</Remember>
